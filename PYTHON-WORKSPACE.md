# IPython Workspace — этап B

Модуль: `lisp/init-python-workspace.el`. Python helper находится рядом:
`lisp/python-workspace-setup.py`; путь вычисляется от файла Elisp, независимо
от текущего проекта и рабочей директории. При загрузке Emacs Python не запускается.

## Первый запуск

1. Откройте `.py` в `python-ts-mode`. Выберите **Работа → Python Workspace →
   Запустить / подключиться** в верхнем меню или в меню правой кнопки мыши.
   Та же команда доступна как `M-x python-workspace-start`.
2. При первом запуске выберите в обычном всплывающем меню `.venv текущей папки`
   (если существует) или `Системный Python`. Вводить путь требуется только для
   пункта `Другой интерпретатор…`. Рабочая папка — папка текущего Python-буфера.
3. Выбор запоминается для папки до закрытия Emacs. Повторный запуск использует
   присоединённый процесс или запомненное окружение, без вопросов о пути.
   Чтобы сменить Python, откройте **Работа → Python Workspace → Окружение Python**.
   Смена окружения не останавливает старую сессию и не переносит её переменные.
4. Для выбора другой рабочей папки есть пункт **Другая рабочая папка…**.
   Основной backend — dREPL. `C-u M-x python-workspace-start` позволяет заново
   выбрать окружение и резервный backend `python` (python.el + IPython + comint-mime).

Верхнее меню **Работа → Запустить Codex IDE** и одноимённый пункт контекстного
меню вызывают существующую команду `codex-ide` для текущего проекта/каталога.
Пункты выполнения Python активны только в подходящем буфере с живой сессией.
Стандартные контекстные пункты сохранены. Treemacs использует своё собственное
контекстное меню; его меню не заменяется.

## Команды

Привязки действуют локально после запуска workspace; `C-s` и Evil `/` сохраняются.
Все команды доступны через `M-x`. Префикс `C-c %` доступен в normal/insert/visual.
В консоли `RET` в Evil insert локально направлен в команду отправки Comint/dREPL;
эта настройка не меняет клавиши других буферов.

| Действие | Команда | Клавиши |
|---|---|---|
| Запуск / выбор workspace | `python-workspace-start` | `C-c % o` |
| Ячейка под курсором | `python-workspace-run-cell` | `C-c % e` |
| Ячейка и переход дальше | `python-workspace-run-cell-and-step` | `C-c % s` |
| Выделение | `python-workspace-send-region` | `C-c % r` |
| Весь буфер, включая несохранённый текст | `python-workspace-run-file` | `C-c % b` |
| Предыдущая / следующая ячейка | `code-cells-backward-cell` / `code-cells-forward-cell` | `C-c % p` / `C-c % n` |
| Редактор ↔ консоль | `python-workspace-switch` | `C-c % z` |
| Выключить локальный режим в редакторе | `python-workspace-mode` | `C-c % q` |
| Остановить процесс и удалить переменные | `python-workspace-stop` | `C-c % k` |

Отключение режима отсоединяет редактор, сохраняя процесс и переменные.
Повторный `python-workspace-start` с теми же параметрами подключит его снова.
Остановить процесс можно из присоединённого редактора или консоли; команда
попросит подтвердить потерю переменных. Ввод в консоль выполняется в Evil insert
state; `RET` отправляет ввод, `C-c C-c` прерывает вычисление средствами Comint.

## Короткая совместная проверка

Создайте собственный пробный `.py`, запустите workspace и выполните ячейки по очереди:

```python
# %% Первая
x = 40

# %% Вторая
x += 2
print(x)  # 42

# %% График
import matplotlib.pyplot as plt
plt.plot([1, 2, 3], [1, 4, 9])
plt.show()

# %% Таблица
import pandas as pd
pd.DataFrame({'a': [1, 2], 'b': [3, 4]})
```

Проверьте переключение `C-c % z`, сохранение `C-s` и поиск `/` в normal state.
Эта визуальная проверка выполняется вместе с пользователем после установки.

## Зависимости и ограничения

Установлены через GNU ELPA: code-cells 0.5, dREPL 0.4, comint-mime 0.7,
mathjax 0.1. Используются существующие Python 3.13.3 и IPython 8.37.0;
глобальное Python-окружение не изменялось. Jupytext установлен пользователем,
но на этапе B не вызывается. Variable Explorer пока отсутствует.

HTML/DataFrame отображаются в консоли штатным comint-mime/vtable, графики —
внутри Emacs. Результаты ограничены: HTML/текстовый MIME — 128 KiB,
остальной MIME — 2 MiB; pandas — максимум 40 отображаемых строк и 12 столбцов;
NumPy сокращает большие массивы. Старый текст консоли обрезается до 3000 строк
и примерно 500000 символов. Ограничения передачи не ограничивают время
вычислений Python и стоимость формирования представления объекта.

Локальный адаптер исправляет percent-encoding временных Windows file URI
в comint-mime 0.7; штатные backend и MIME-renderer не заменены.
LaTeX зависит от работоспособности MathJax/Node; визуально на этапе B не проверен.

Прямое автоматическое преобразование `.ipynb` пакетом code-cells отключено,
поскольку оно теряет сохранённые outputs. Нет синхронизации или выполнения
при сохранении. Результаты REPL не записываются в notebooks.

## Откат

1. Остановите нужные workspace командой `python-workspace-stop`.
2. Удалите строки `(require 'init-workspace-menu)` и
   `(require 'init-python-workspace)` из `init.el` и
   перезапустите Emacs. Остальная Python-конфигурация остаётся прежней.
3. При желании удалите `init-workspace-menu.el`, `init-python-workspace.el`,
   `python-workspace-setup.py` из `lisp` и эту инструкцию.

Исходный `init.el` сохранён в отдельном каталоге `backups/python-workspace-stage-b-*`.
Его можно восстановить целиком, если после установки `init.el` не менялся.
Установленные ELPA-пакеты оставлены на диске. Для полного удаления используйте
`M-x package-delete` (после отключения модуля); code-cells регистрирует свой
автоматический обработчик `.ipynb` при активации пакета независимо от workspace.
Не открывайте и не сохраняйте notebooks через этот обработчик.
