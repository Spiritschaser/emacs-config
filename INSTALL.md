# Установка конфигурации

Проверено на Windows с GNU Emacs 31.1. Для используемых пакетов нужен
Emacs не ниже 29.1; другие версии и Linux требуют отдельной проверки.

Скопировать конфигурацию в каталог `user-emacs-directory` (обычно
`~/.emacs.d/`), включая `lisp/` и `patches/`, и запустить Emacs.
Каталоги `elpa/`, `codex-ide-backup/` и кэши переносить не нужно.

При первом запуске потребуется сеть. `lisp/init-packages.el` подключает
встроенный менеджер пакетов и `use-package`, сохраняя стандартные архивы
GNU/NonGNU ELPA и добавляя уже использовавшийся MELPA. Каждый внешний
пакет объявлен в своём тематическом модуле `lisp/init-*.el`; недостающие
пакеты и их зависимости устанавливаются автоматически. Встроенные
библиотеки и собственные модули подключаются через `require`.
При следующих запусках установленные пакеты повторно не скачиваются.
Автоматического обновления до новых версий нет.

## Codex IDE

`lisp/init-codex.el` устанавливает `codex-ide` через `package-vc` из
`https://github.com/dgillis/emacs-codex-ide` непосредственно в
`elpa/codex-ide/`. Одноимённый пакет другого автора из архивов не используется.
Свежая установка закреплена на ревизии
`5eba84dd58ad8609e8f7e8c4159d4aac90b4f303`, совместимой с локальным патчем.

До загрузки Codex автоматически проверяется и при необходимости применяется
`patches/codex-ide-emacsclient-server-file.patch`. Повторное применение
распознаётся проверкой обратного патча. При конфликте загрузка останавливается
с ошибкой; чужой или частично изменённый код не исправляется слепой заменой.
Подробности обновления и отката — [patches/README.md](patches/README.md).

## Что устанавливается отдельно

Менеджер Emacs устанавливает Lisp-пакеты. Для соответствующих функций
нужны программы в `PATH`: Git, Python, Codex CLI, а также используемые
Ruff, BasedPyright, PostgreSQL-клиент и другие внешние инструменты.
Python workspace дополнительно требует подготовки Python-окружения,
описанной в [PYTHON-WORKSPACE.md](PYTHON-WORKSPACE.md).
Грамматики Tree-sitter и шрифты отдельно не скачиваются этой настройкой;
без Markdown-грамматик используется обычный `markdown-mode`.

В `init.el` сохранён существующий адрес прокси `http://192.168.1.1:8080`.
На другом компьютере его нужно изменить или убрать блок настройки прокси,
если этот адрес недоступен. Файл `sql-connections.el` с личными подключениями
не входит в Git и необязателен для запуска.

Настройки пакетов следует добавлять в соответствующий тематический модуль,
например `(use-package имя-пакета ...)`. Автоматическая установка включена
по умолчанию; для встроенной библиотеки используется `:ensure nil`.

## Проверка установки

Из корня конфигурации:

```bash
emacs -Q --batch -l tests/package-startup-check.el
```

Проверка использует отдельные пакеты и сервер в `.cache/package-startup-test/`.
Первый запуск скачивает недостающее, повторный использует уже установленное.
Переменная окружения `EMACS_CONFIG_TEST_DIRECTORY` позволяет выбрать другой
пустой каталог. Затем выполняются проверки патча, повторного запуска,
автозагрузки Codex и выбора Markdown-режима. Основная сессия не перезапускается.
