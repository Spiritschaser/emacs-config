# Локальный патч Codex IDE

Установка описана в [INSTALL.md](../INSTALL.md).
`lisp/init-codex.el` скачивает пакет из GitHub в `elpa/codex-ide/`
и применяет патч до загрузки моста. Каталог `codex-ide-backup/` больше
не используется новой установкой и сохраняется как резервная копия.

Базовая ревизия GitHub и свежей установки:
`5eba84dd58ad8609e8f7e8c4159d4aac90b4f303`.

`codex-ide-emacsclient-server-file.patch` содержит исправления Python-прокси,
Lisp-моста и тесты. TCP использует `--server-file`, Unix-сокет —
`--socket-name` вместо безусловного `-s`. Транспорт передаётся явно.
Также исправлен запуск сервера при состоянии `:other`, восстановление
устаревшего подключения и проверка владельца TCP-файла.
Подробности: [EMACS-SERVER.md](../EMACS-SERVER.md).

## Проверка при запуске

1. `git apply --reverse --check` определяет уже применённый патч.
2. Иначе `git apply --check` проверяет совместимость, затем патч применяется.
3. Lisp-мост компилируется заново, чтобы не загрузить старый `.elc`.
4. Конфликт, частично применённый патч или отсутствующий файл патча
   останавливает загрузку Codex с диагностикой. Сброса локальных правок нет.

## Обновление

Выполнять после завершения сессий Codex, использующих обновляемый мост.
Сначала сохранить полную копию `elpa/codex-ide/` с `.git` и локальными
изменениями, а также конфигурацию и патч. Из корня `.emacs.d`:

```bash
git -C elpa/codex-ide status --short
git -C elpa/codex-ide diff
```

Проверить, что изменения исходников соответствуют патчу. Не использовать
`reset --hard`, `clean`, `--reject` или принудительное применение.
`codex-ide-autoloads.el` также меняется при штатной генерации автозагрузок,
а `codex-ide-pkg.el` создаётся менеджером пакетов; это ожидаемые изменения.
Следующие команды выполнять по одной, продолжая только после успеха:

```bash
git -C elpa/codex-ide apply --reverse --check ../../patches/codex-ide-emacsclient-server-file.patch
git -C elpa/codex-ide apply --reverse ../../patches/codex-ide-emacsclient-server-file.patch
```

После сохранения полной копии восстановить только автоматически
сгенерированный файл, чтобы его локальное изменение не мешало обновлению:

```bash
git -C elpa/codex-ide restore -- codex-ide-autoloads.el
```

Обновить пакет штатной командой `M-x package-vc-upgrade`, выбрав `codex-ide`.
Затем проверить применимость патча:

```bash
git -C elpa/codex-ide apply --check ../../patches/codex-ide-emacsclient-server-file.patch
```

При успехе следующий запуск Emacs сам применит патч и пересоберёт мост.
Если проверка не прошла, сначала адаптировать патч к новому коду либо
восстановить сохранённый checkout. Если upstream уже содержит исправление,
нужно отдельно пересмотреть патч и проверку в `init-codex.el`.
Для воспроизводимости новых установок обновить `my/codex-ide-revision`
после проверки новой ревизии. Уже установленные пакеты при запуске
автоматически не обновляются и не откатываются к закреплённой ревизии.

В новой сессии Codex проверить MCP `emacs_get_all_buffers`.

## Переход со старой установки

Старый `elpa/codex-ide/` содержал только перенаправление в
`codex-ide-backup/`. Его следует сохранить в `backups/` и убрать из `elpa/`
перед новым запуском Emacs: пакет будет скачан заново штатным способом.
Сам `codex-ide-backup/` не удалять, пока открытая сессия его использует.
Новая конфигурация отказывается использовать старое перенаправление.

## Откат

Сохранить новые каталоги отдельно, восстановить предыдущие файлы
конфигурации и прежний `elpa/codex-ide/`, затем перезапустить Emacs.
Не смешивать загруженные модули из разных checkout в одной сессии.
Исторический снимок `backups/codex-ide-working-20261110-222632/`
содержит прежний checkout, файлы подключения и `RESTORE.md`.
Он не включает всю установку Emacs, Python и Codex CLI.
