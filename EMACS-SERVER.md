# Emacs server и MCP: запуск, диагностика и восстановление

## Причина сбоя 13 ноября 2026

MCP-прокси Python работал, но emacsclient получал отказ соединения.
Текущий Emacs имел PID 14776, файл `server/server` указывал на уже
завершившийся PID 16232 и порт 51396 без слушателя. Файл был создан
раньше текущего Emacs. Причина некорректного завершения старого процесса
не установлена; доказан сбой восстановления при следующем запуске.

`server-running-p` в Emacs 31.1 на Windows вернул `:other` для этого
файла. Проверка `(unless (server-running-p) (server-start))` ошибочно
считала любое ненулевое значение признаком работающего сервера. Такая
же проверка в мосте пропускала запуск. Отдельный старый Python-патч
всегда выбирал TCP и тем самым нарушал переносимость на Unix-сокеты.

## Что происходит при запуске

`lisp/init-codex.el` сначала определяет путь подключения из `server-use-tcp`,
затем включает мост. TCP использует `server-auth-dir` и `--server-file`;
Unix-сокет — `server-socket-dir` и `--socket-name`. Выбор транспорта явный,
а не только по названию ОС. TCP на Linux/Unix тоже поддерживается.

Мост проверяет живой `server-process` текущего Emacs. При отсутствии
сервера штатный `server-start` восстанавливает устаревший файл или сокет.
Ненулевой `:other` не означает, что сервер работает. Работающий сервер
другого процесса не перехватывается. Живой PID в TCP-файле считается
основанием остановиться для диагностики, даже если PID переиспользован
другой программой. Файл текущего Emacs с остановленным listener может
быть удалён для перезапуска. Результат запуска проверяется; PID,
транспорт и путь записываются в `*Messages*` без ключа авторизации.

Штатное завершение Emacs уже вызывает `server-force-stop` из
`kill-emacs-hook` и убирает своё подключение. При аварии/принудительном
завершении этот hook может не выполниться. Очистка при следующем запуске
нужна независимо от штатного завершения. Внешний скрипт удаления не нужен.

## Если MCP снова недоступен

1. В самом Emacs выполнить `M-x emacs-server-health`.
   Буфер `*Emacs server health*` показывает текущий PID, транспорт,
   путь, наличие файла, PID владельца TCP-файла, состояние проверки
   и собственного listener. Ключ авторизации не выводится.
   На Unix у сокета нет TCP-заголовка с PID — эти поля будут nil.
2. Выполнить `M-x emacs-server-recover`. При устаревшем подключении
   сервер восстановится. Для другого живого владельца будет ошибка;
   сначала выяснить, какому процессу он принадлежит. Вручную стирать
   файл по одному лишь факту отказа соединения нельзя.
3. Повторить MCP-вызов, например `emacs_get_all_buffers`. Команда
   health проверяет локальное состояние, а не полную цепочку MCP.
   Если сервер исправен, а MCP недоступен, отдельно проверить процесс
   Python-прокси, путь emacsclient и аргументы транспорта.

Существующий Python-прокси читает файл подключения при каждом вызове,
поэтому смена TCP-порта при восстановлении не требует его перезапуска.
Если изменён сам транспорт или путь подключения, нужна новая сессия
Codex, чтобы получить новые аргументы запуска MCP.

## Однократное применение к уже открытой сессии без сервера

Через `M-:` выполнить:

```elisp
(progn
  (load (expand-file-name "elpa/codex-ide/codex-ide-mcp-bridge.el"
                          user-emacs-directory))
  (load (expand-file-name "lisp/init-codex.el" user-emacs-directory)))
```

При следующих запусках это делает конфигурация. Код использует
`user-emacs-directory`, без Windows-путей.

## Проверки

Для текущей установки используйте команды диагностики выше и вызов MCP
`emacs_get_all_buffers`. При разработке патча 42 ERT и 3 Python-теста
прошли на Windows / Emacs 31.1 / Python 3.13. Отдельные тестовые файлы
той проверки в текущем репозитории отсутствуют.
TCP проверен со штатным сервером в изолированном временном каталоге:
нет файла, файл погибшего PID, повторный запуск, потеря listener,
штатная остановка с удалением файла. Unix-ветки и выбор аргументов
проверены с подменой системных вызовов. Реального Linux/Unix в среде
нет, поэтому запуск там пока не подтверждён.

Правки пакета сохранены в `patches/codex-ide-emacsclient-server-file.patch`.
Порядок обновления пакета описан в [руководстве по патчу](patches/README.md). Сам установленный
checkout `elpa/codex-ide/` исключён из основного Git, поэтому этот
патч необходимо переносить вместе с конфигурацией.
