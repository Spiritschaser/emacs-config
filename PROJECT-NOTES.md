# Продолжение настройки GNU Emacs 31.1 — Windows/Linux

Это продолжение большого технического диалога по настройке Emacs. Используй приведённую ниже информацию как актуальный контекст, но сверяй конкретный код с приложенными конфигурационными файлами.

## 1. Цели и принципы

Настраиваем GNU Emacs 31.1 на Windows 11 с возможностью переноса конфигурации на Linux.

Основные требования:

- Чистая модульная конфигурация, без Doom Emacs как дистрибутива.
- Evil, привычные Windows-сочетания клавиш.
- Приятная тёмная тема, Doom Modeline, монохромный toolbar.
- Treemacs для дерева файлов.
- Встроенный Tree-sitter для поддерживаемых языков.
- Python: `python-ts-mode`, Eglot + BasedPyright, Ruff/Flymake, Corfu.
- SQL: PostgreSQL в первую очередь, дополнительно ClickHouse и SQLite.
- Предпочтение готовым штатным решениям вместо больших пользовательских костылей.
- Изменения минимальные, переносимые, проверяемые по одному шагу.
- Не предлагать перезапускать Emacs без необходимости.
- Не менять работающие компоненты ради побочных улучшений.
- Если API или версия пакета не проверены, сначала проверить их, а не предлагать непроверенный код.

## 3. Что уже работает

### Интерфейс

- Evil.
- Windows-подобные клавиши.
- Treemacs.
- Doom Modeline.
- Монохромный toolbar.
- Тёмная тема.
- `global-tab-line-mode` — вкладки буферов в каждом окне.
- `context-menu-mode` — обычное контекстное меню по ПКМ.
- Штатное нежелательное поведение ПКМ (`mouse-save-then-kill`) отключалось через глобальный remap.
- Отдельные вкладки SQLi и Clutch работают.

### Python

- `python-ts-mode`.
- Eglot + BasedPyright.
- Ruff.
- Corfu.
- Tree-sitter.

В Eglot была сложная проблема с регистрацией файловых наблюдателей. Она решена настройкой capabilities. Не менять её без необходимости.

### Treemacs

На Windows `python3.exe` указывал на WindowsApps и вызывал `exited abnormally with code 49`.

Исправили переносимой настройкой выбора настоящего Python:

- Windows: `executable-find "python"`.
- Linux: сначала `python3`, затем `python`.

Настройка в `init-treemacs.el`, внутри `with-eval-after-load 'treemacs`, через `setq treemacs-python-executable`.

После исправления Treemacs работает.

### SQLi

Встроенный `sql-mode` работает в диалекте PostgreSQL.

SQLi подключается к PostgreSQL 17 через `psql.exe`, выполняет выделенные запросы из `.sql` и возвращает результаты.

Используется `sql-connection-alist` из `sql-connections.el`.

Для Windows настроена передача пароля через `PGPASSWORD`, UTF-8 и английская локаль процесса `psql`:

- `LC_ALL=C`
- `LC_MESSAGES=C`
- `LANG=C`
- `LANGUAGE=C`
- `PGCLIENTENCODING=UTF8`

После исправлений русские данные показываются корректно, а служебные сообщения имеют вид `(1 row)`.

### Clutch

Установлены пакеты:

- `clutch` — версия на момент установки `20261103.926`.
- `pgsql` — PostgreSQL backend.

Clutch успешно подключается к тому же PostgreSQL, что SQLi.

Сделан адаптер в `init-sql.el`, который преобразует `sql-connection-alist` в `clutch-connection-alist`. Список серверов и паролей остаётся единым.

При преобразовании значения `(sql-product 'postgres)` важно учитывать форму `(quote postgres)`.

Для PostgreSQL Clutch потребовалось добавить:

`:sslmode 'require`

После этого подключение заработало.

Через Clutch уже успешно выполнен запрос:

```sql
SELECT 1 AS test, 'Проверка Clutch' AS message;
```

Результат открылся в интерактивной таблице с колонками `test` и `message`. Русский Unicode отображается правильно.

SQLi и Clutch — независимые соединения, но используют один источник настроек.

## 4. Контекстное меню SQL

Для `.sql` работает штатное контекстное меню Emacs.

В `init-sql.el` добавлено пользовательское подменю «Подключиться к БД», в котором подключения выбираются мышью из `sql-connection-alist`.

Штатное `SQL → Start...` отображалось неактивным, поэтому его не переделывали.

Не нужно реализовывать команду «Выполнить SQL-запрос под курсором». Пользователь от неё отказался.

Достаточно выполнять выделенный SQL или весь файл.

## 5. Tree-sitter SQL

Исследовали возможность подсветки SQL внутри многострочных Python f-строк.

Пытались использовать SQL Tree-sitter DLL, в том числе самостоятельно собранную грамматику `m-novikov/tree-sitter-sql` через Zig на Windows.

При некоторых разборах происходили нативные аварийные завершения Emacs.

Пользователь решил пока отложить эту задачу.

Не предлагать возвращаться к ней и не подменять её большой самодельной системой Font Lock, пока не будет прямого запроса.

## 6. Текущая задача — контекстные меню Clutch

Последний достигнутый результат: Clutch выполнил SQL и показал интерактивную таблицу.

Пользователь попросил вывести часто используемые команды Clutch в контекстное меню.

В предыдущем чате был предложен код для `init-sql.el`, добавляющий разные меню в:

1. SQL-консоль Clutch (`clutch-mode`).
2. Таблицу результатов (`clutch-result-mode`).

В SQL-консоли нужны:

- Выполнить выделение.
- Выполнить буфер.
- Показать результат.
- Выбрать подключение.
- Переключить схему.
- Показать объекты базы.

В таблице нужны:

- Просмотр значения или записи.
- Сортировка.
- Фильтрация.
- Пагинация.
- Копирование CSV/TSV.
- Экспорт.
- При необходимости редактирование ячеек и применение изменений.

**Критически важно: предложенный код контекстных меню Clutch ещё НЕ подтверждён как работающий.**

Перед его применением нужно проверить API установленного Clutch, существующие команды и режимы. Не предполагать, что все названия функций существуют или что обработчики работают корректно.

Не использовать дополнительные пакеты для меню без необходимости.

Контекстное меню Clutch не должно ломать уже работающие меню SQLi и `.sql`.

## 7. Как продолжать работу

Начать с проверки текущего `init-sql.el` и, если нужно, других приложенных модулей.

Сначала установить, был ли добавлен код контекстного меню Clutch. Если был — проверить корректность и предложить минимальные исправления.

Далее проверить меню непосредственно в SQL-консоли и таблице результатов.

Работать постепенно, с короткими, проверяемыми шагами. Не переписывать всю конфигурацию и не создавать сложные вспомогательные системы без необходимости.

Не включать `clutch-mode` автоматически для всех `.sql`, пока пользователь не решит это отдельно.

## 8. Clutch — реализованные контекстные меню

Настройка контекстных меню Clutch выполнена и проверена в GNU Emacs 31.1.

### SQL-консоль (`clutch-mode`)

В `init-sql.el` добавлена функция `my/clutch-context-menu`, использующая штатный механизм `context-menu-functions`.

Работают пункты:

- **Выполнить выделение** — `clutch-execute-region`, доступен при активном выделении.
- **Выполнить весь SQL** — `clutch-execute-buffer`.
- **Выбрать подключение…** — `clutch-connect`.
- **Переключить схему…** — `clutch-switch-schema`.
- **Показать объекты БД…** — `clutch-object-browse`.

Для просмотра объектов добавлена обёртка `my/clutch-browse-objects`, вызывающая `minibuffer-completion-help` через `minibuffer-with-setup-hook`. Список объектов открывается без дополнительного нажатия `TAB`.

При выборе таблицы Clutch формирует соответствующий SQL-запрос.

При наличии единственного подключения `ra1` команда `clutch-connect` выбирает его автоматически.

Меню SQLi и обычных `.sql` не затронуты.

### Таблица результатов (`clutch-result-mode`)

Добавлено контекстное меню через `my/clutch-result-context-menu`.

Работает пункт:

- **Просмотреть запись вертикально** — `clutch-result-open-record`.

Команда открывает отдельный буфер с транспонированным представлением выбранной строки: названия полей слева, значения справа.

Важно: не вызывать `clutch-record-mode` напрямую — это переключение major mode, а не открытие Record View.

### Вертикальный просмотр (`clutch-record-mode`)

Добавлено отдельное контекстное меню через `my/clutch-record-context-menu`.

Проверены и работают:

- **Следующая запись** — `clutch-record-next-row`.
- **Предыдущая запись** — `clutch-record-prev-row`.

Record View открывается в отдельном окне под таблицей результатов.

Для закрытия окна можно использовать `C-x 0`. Для уничтожения буфера — `C-x k`. Штатную клавишу выхода `q` необходимо проверять по фактической раскладке клавиш режима.

### Что осталось по Clutch

- Фильтрация результатов по значению выбранной ячейки через контекстное меню.
- Выполнение выделенного SQL в новой независимой вкладке результатов без потери предыдущего результата.
- Удобное копирование и экспорт CSV/TSV.
- При необходимости — пагинация и редактирование ячеек.

Сортировка уже реализована автором Clutch через нажатие на заголовок столбца. Дублировать её не требуется.

**Работа над новыми возможностями Clutch приостановлена.** Не реализовывать фильтрацию и независимые вкладки без дополнительной проверки API и архитектуры пакета.

## 9. Управление окнами и вкладками Emacs

### Разворачивание окна двойным щелчком

В `init-ui.el` добавлена и проверена функция:

`my/tab-line-toggle-maximize`

Двойной щелчок по вкладке `tab-line`:

- Первый — сохраняет текущую конфигурацию окон и разворачивает выбранное окно.
- Повторный — восстанавливает предыдущую конфигурацию, включая Treemacs, SQL-консоль и результаты Clutch.

Используются штатные `current-window-configuration`, `set-window-configuration`, `delete-other-windows` и параметр фрейма `my/saved-window-config`.

Обработчик подключён через `tab-line-tab-map` к событию `[tab-line double-down-mouse-1]`.

**Проверено: работает отлично.** Одинарный щелчок по вкладке не изменён.

В терминальном Emacs сама логика управления окнами применима, но получение двойного щелчка зависит от возможностей терминала.

### Закрытие вкладок крестиком

В `init-ui.el` добавлена и проверена функция:

`my/tab-line-close-buffer`

Подключена через штатную переменную:

`tab-line-close-tab-function`

Поведение:

- Если в окне несколько вкладок — уничтожает выбранный буфер, окно сохраняет.
- Если вкладка последняя — уничтожает буфер и закрывает окно, если остаются другие окна.
- Если окно последнее — сохраняет окно, чтобы не закрывать фрейм.
- Если буфер отображается в нескольких окнах — его уничтожение отражается во всех них.
- Для изменённых файлов сохраняются штатные предупреждения Emacs о несохранённых изменениях.

**Проверено: работает отлично.** Пользователь особенно оценил поведение при отображении одного буфера в нескольких окнах.

### Ручное сохранение расположения окон

Штатные команды:

- `C-x r w c` — сохранить конфигурацию окон в регистр `c`.
- `C-x 1` — развернуть текущее окно.
- `C-x r j c` — восстановить конфигурацию.

Эта возможность полезна как дополнительный способ управления окнами, хотя двойной щелчок стал основным.

## 10. Следующий этап — интеграция Codex с Emacs

Пользователь хочет превратить Emacs в среду, где AI-агент может изучать работающий редактор, анализировать конфигурацию, диагностировать проблемы, предлагать и проверять изменения.

**Принципиальное требование: нативный графический интерфейс Emacs, а не терминальный интерфейс агента.**

Терминальный CLI допустим в качестве внутреннего движка, но взаимодействие должно происходить через обычные буферы, окна, вкладки, меню, diff и элементы управления Emacs.

### Рассмотренные проекты

**Thanos Apollo — `codex-ide`**

- Репозиторий: https://git.thanosapollo.org/emacs-codex-ide
- Codex CLI запускается через Eat.
- Имеется MCP-интеграция.
- Распространяется через NonGNU ELPA.
- Не выбран из-за терминального пользовательского интерфейса.

**Duncan Gillis — `emacs-codex-ide`**

- Репозиторий: https://github.com/dgillis/emacs-codex-ide
- Использует `codex app-server`.
- Предоставляет нативный интерфейс Emacs.
- Поддерживает MCP-мост для взаимодействия с работающим редактором.
- Предусматривает работу с сессиями, изменениями файлов и подтверждениями действий.

По результатам сравнения **выбран проект Duncan Gillis** как основной кандидат для установки.

На 9 ноября 2026 года при предыдущей проверке для проекта сообщалось около 109 GitHub Stars и 19 форков. Эти показатели не являются оценкой активных пользователей; актуальные значения необходимо перепроверять.

### Требования к интеграции

- Отдельный модуль `init-codex.el`.
- Совместимость с Windows 11 и последующим переносом на Linux.
- Использование существующего `package.el` / `use-package`, если это поддерживается пакетом.
- Нативный интерфейс без терминальной эмуляции.
- Управление сессиями агента из Emacs.
- Просмотр и подтверждение изменений кода.
- Доступ к текущему проекту, буферам и выделениям.
- MCP-доступ к живому состоянию Emacs.
- Проверка команд, major modes, keymaps и функций через работающий редактор.
- Защита файлов с паролями и другими секретами.
- Минимальные изменения существующей конфигурации.
- Сначала запуск и проверка базового интерфейса без MCP, затем подключение MCP.

Авторизация и сеть
- Codex CLI авторизован через ChatGPT Plus командой codex login в Windows. Не требуется API-ключ; не копировать токены с другого Linux-компьютера с VS Code.
- Настройки прокси добавлены постоянно в `init.el`, в блок `Network proxy for Codex CLI` перед загрузкой пользовательских модулей (проверено по файлу 10 ноября 2026):
  ```elisp
  (let ((proxy "http://192.168.1.1:8080"))
    (setenv "HTTP_PROXY" proxy)
    (setenv "HTTPS_PROXY" proxy)
    (setenv "ALL_PROXY" proxy)
    (setenv "NO_PROXY" "localhost,127.0.0.1,::1"))
  ```
- Блок задаёт окружение процесса Emacs и наследуется запускаемыми из него дочерними процессами, включая `codex app-server`. Это не системная настройка Windows и не отдельная настройка встроенного HTTP-клиента Emacs. Блок выполняется без ограничения на Windows; при переносе на Linux нужно проверить доступность указанного прокси.
- `NO_PROXY` исключает локальные адреса из проксирования для клиентов, поддерживающих эту переменную. Уже запущенные дочерние процессы не получают новое окружение автоматически.
- В текущем диалоге обмен сообщениями работает; отдельная проверка всех сетевых обращений через прокси и загрузки этих настроек при чистом запуске Emacs не проводилась.
